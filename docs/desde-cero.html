CONCEPTOS Y FRONTERAS

Antes de empezar: qué hace y qué NO hace Clue.

Vamos a trabajar con un programa mínimo en Python: una función de cálculo de totales en total.py. La guía se verifica en Linux; las variantes Windows/macOS se inspeccionan, sin piloto con una persona principiante. No hace falta clonar el código fuente de Oracle Clue; lo instalaremos como una herramienta de terminal independiente mediante uv.

Una terminal es una ventana para escribir comandos: PowerShell en Windows, Terminal en macOS o cualquier terminal en Linux. Un editor de texto plano (como Visual Studio Code) permite editar código y archivos JSON y guardarlos como texto UTF-8. En el editor elegí Archivo → Abrir carpeta para abrir laboratorio-clue cuando lo crees. En Windows activá las extensiones de nombre de archivo para evitar total.py.txt. Cada bloque que define un archivo es contenido para pegar en el editor; los bloques de comandos se ejecutan en la terminal. Git conserva las versiones de los archivos.

Frontera fundamental de Clue 0.1.0a1

Oracle Clue NO llama a modelos de inteligencia artificial ni busca defectos automáticamente. Tampoco aprueba código ni garantiza que esté libre de errores. Clue comprueba dos cosas sobre el contexto seleccionado: que el paquete de contexto represente exactamente los commits de Git sin omisiones silenciosas, y que el informe técnico señale líneas dentro de los rangos del diff, que también incluyen contexto sin modificar. La revisión y aprobación final siempre corresponden a una persona capacitada.

PASO 01

Instalá las herramientas necesarias.

Asegurate de tener Git instalado. Luego instalá uv, el gestor moderno de paquetes de Python, según tu sistema operativo:

Windows · PowerShell 
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
macOS o Linux · Terminal 
curl -LsSf https://astral.sh/uv/install.sh | sh

Alternativa con wget si no tenés curl:

wget -qO- https://astral.sh/uv/install.sh | sh

Cerrá y volvé a abrir tu terminal. Comprobá que las herramientas respondan:

git --version
uv --version

Instalá Python 3.13 e instalá Oracle Clue desde PyPI en un entorno aislado con uv tool:

uv python install 3.13
uv tool install --python 3.13 oracle-clue==0.1.0a1
uv tool update-shell

Volvé a abrir tu terminal y comprobá que Clue esté disponible:

oracle-clue --version

Esperamos la salida exacta: oracle-clue 0.1.0a1.

Nota: También podés ejecutar Clue sin instalación permanente usando uvx --from oracle-clue==0.1.0a1 oracle-clue --help.

PASO 02

Creá un repositorio de prueba nuevo.

Creá una carpeta vacía para tu prueba en tu directorio de trabajo (por ejemplo en tu carpeta personal). No clones el repositorio de Clue:

mkdir laboratorio-clue
cd laboratorio-clue
git init

Configurá una identidad local de Git para este repositorio:

git config user.name "Tu Nombre"
git config user.email "tu-correo@example.invalid"

Abrí la carpeta laboratorio-clue en tu editor de texto. Creá un archivo llamado total.py con este contenido inicial completo:

def calcular_total(precio: float, cantidad: int) -> float:
    return precio * cantidad

Guardá el archivo y creá el primer commit (que servirá como base):

git add total.py
git commit -m "Implementar cálculo de total original"
¿Por qué necesitamos dos commits en Git?

Clue compara dos estados confirmados en el historial de Git (un commit base y el commit HEAD). Un repositorio nuevo con un solo commit no tiene un commit padre con el que comparar diferencias. Por eso Clue requiere que exista un commit base que difiera de HEAD.

PASO 03

Introducí un cambio con un defecto real y visible.

En tu editor, abrí total.py y modificá la línea 2: reemplazá el operador de multiplicación * por el de suma +. El archivo completo debe quedar así:

def calcular_total(precio: float, cantidad: int) -> float:
    return precio + cantidad

El error es evidente: si compramos 3 unidades a $10.0, la función devolverá 13.0 en lugar de 30.0.

Guardá el archivo y confirmá el segundo commit (que será tu HEAD):

git add total.py
git commit -m "Modificar cálculo de total con defecto sembrado"

Comprobá que el árbol de trabajo esté completamente limpio:

git status

Debe indicar que no quedan cambios por confirmar (el texto puede estar traducido). Para comprobarlo sin depender del idioma, git status --porcelain no debe imprimir nada en este ejemplo.

La exigencia de un árbol limpio

Clue revisa commits reales. Si hay cambios locales sin confirmar o archivos modificados en stage, Clue se detiene con el error: CLUE: hay cambios versionados sin commit; confirmalos o usá un checkout limpio. Esto previene presentar como revisado código que aún no forma parte del historial trazable. Archivos ignorados por .gitignore o no versionados tampoco entran al diff.

PASO 04

Agregá un archivo de contexto explicativo.

Clue permite adjuntar archivos del repositorio para que el revisor conozca las especificaciones o reglas de negocio sin tener que clonar todo el proyecto. Creá en la raíz del repo un archivo llamado especificacion.md:

# Especificación de Cálculo
El total debe calcularse como el producto aritmético del precio unitario por la cantidad.

Podés dejarlo en el árbol o commitearlo. Para este ejemplo, lo commiteamos:

git add especificacion.md
git commit -m "Agregar especificación de cálculo"

Las rutas pasadas a --contexto se resuelven siempre desde la raíz del repo y no pueden apuntar a enlaces simbólicos ni a archivos de más de 256 KB.

PASO 05

Prepará el paquete de revisión.

Creá una carpeta fuera de tu repositorio para guardar los artefactos de la revisión (por ejemplo, en la carpeta superior):

Comando según tu sistema operativo 
mkdir ../revisiones

Ahora ejecutá oracle-clue preparar. Comparamos contra HEAD~2 (el commit previo a los cambios de código y especificación), o podés usar el hash del primer commit:

oracle-clue preparar --repo . --base HEAD~2 --contexto especificacion.md --salida ../revisiones/contexto.json

Esperamos la salida:

Paquete preparado: ../revisiones/contexto.json; omisiones: 0. No es un informe de revisión.
Reglas obligatorias de --salida

1. Fuera del repositorio: Si intentás guardar el archivo dentro de la carpeta del repo, Clue arrojará el error CLUE: guardá el paquete fuera del repo revisado.
2. Archivo nuevo: Clue abre el destino en modo exclusivo ('x'). Si contexto.json ya existía, fallará para evitar sobreescrituras accidentales de paquetes previos.
3. Stdout por defecto: Si no especificás --salida, Clue imprime el JSON directamente por terminal.

Abrí ../revisiones/contexto.json en tu editor. Observá los campos clave:

  • diff_sha256: Hash criptográfico SHA-256 del diff raw de Git.
  • context_sha256: Huella de la representación compacta del paquete antes de agregar el propio campo context_sha256; incluye diff, textos, contextos, omisiones y metadatos.
  • files: Muestra los archivos modificados, su texto anterior (base_text), su texto actual (head_text), el parche unificado y los rangos de línea ranges:
    "ranges": { "base": [[1, 2]], "head": [[1, 2]] }.
  • limitations: Clue declara de forma explícita que preparar contexto no ejecuta revisiones de IA ni aprobación humana.
Límites técnicos estrictos de Clue

• Máximo 200 archivos en el diff.
• Máximo 256 KB por archivo o blob de contexto.
• Máximo 1 MB para el paquete serializado compacto.
• Omisión automática de credenciales conocidas (.env, .ssh, id_rsa, *.pem, *.key) y de archivos binarios.
• Seguridad: El filtro de nombres no garantiza ausencia de secretos en otros archivos normales. El operador debe revisar el contenido de contexto.json antes de entregarlo a un tercero. Clue no envía datos a internet.

PASO 06

Redactá el informe de revisión (Asistente Python).

Un revisor técnico (humano o modelo externo) lee contexto.json y genera un informe conforme a hallazgos.schema.json.

Para no tener que copiar manualmente los hashes SHA-256 ni recurrir a comandos opacos de terminal, creamos un archivo Python completo y transparente llamado armar_informe.py en la raíz de tu proyecto. Este script es un simple asistente de documentación para armar el JSON; Clue no genera hallazgos automáticamente.

Creá el archivo armar_informe.py en tu editor con este código completo:

"""Asistente documental para generar informe.json de ejemplo.
Lee contexto.json real y arma un informe conforme a hallazgos.schema.json.
Clue NO produce hallazgos automáticamente; este script es solo un facilitador."""
from pathlib import Path
import json

def main():
    paquete_path = Path("../revisiones/contexto.json").resolve()
    if not paquete_path.exists():
        raise SystemExit(f"No se encontró {paquete_path}. Ejecutá el paso 5 primero.")

    bundle = json.loads(paquete_path.read_text(encoding="utf-8"))

    cambiado = next((item for item in bundle["files"] if item["file"] == "total.py"), None)
    if not cambiado or len(cambiado["head_text"].splitlines()) < 2 or cambiado["head_text"].splitlines()[1].strip() != "return precio + cantidad":
        raise SystemExit("Este asistente solo documenta el defecto de este ejemplo; revisá el paquete antes de generar otro informe.")

    informe = {
        "schema_version": "oracle-clue.review/v1",
        "repo": bundle["repo"],
        "base": bundle["base"],
        "head": bundle["head"],
        "diff_sha256": bundle["diff_sha256"],
        "context_sha256": bundle["context_sha256"],
        "provider": {
            "name": "Revisor humano de ejemplo",
            "model": None
        },
        "review_status": "completo",
        "limitations": [],
        "findings": [
            {
                "id": "HALLAZGO-01",
                "kind": "bug",
                "severity": "alta",
                "confidence": 1.0,
                "title": "Operación de suma en lugar de multiplicación",
                "explanation": "calcular_total devuelve precio + cantidad en lugar de precio * cantidad.",
                "location": {
                    "file": "total.py",
                    "side": "head",
                    "start_line": 2,
                    "end_line": 2
                },
                "trigger": "Llamar con precio=10.0 y cantidad=3 devuelve 13.0 en vez de 30.0.",
                "evidence": "Línea 2 en head_text: return precio + cantidad",
                "related_requirement": None,
                "status": "pendiente",
                "verification": "Ejecutar una prueba unitaria: assert calcular_total(10.0, 3) == 30.0"
            }
        ]
    }

    salida = Path("../revisiones/informe.json")
    with salida.open("x", encoding="utf-8") as file:
        file.write(json.dumps(informe, indent=2, ensure_ascii=False) + "\n")
    print(f"Informe redactado con éxito en: {salida}")

if __name__ == "__main__":
    main()

Ejecutá el asistente desde tu terminal:

uv run --no-project --python 3.13 python armar_informe.py
Por qué status: "pendiente" es obligatorio

El schema hallazgos.schema.json exige que todo hallazgo emitido por un revisor esté en estado pendiente. Ningún modelo de IA ni revisor externo puede marcar un hallazgo como aprobado, corregido o descartado en este archivo. Esas decisiones pertenecen exclusivamente al registro de decisiones.

PASO 07

Validá la integridad del informe con Clue.

Llegó el momento de ejecutar la validación de Clue. Este comando conecta el informe con el paquete y con el estado vivo de tu repositorio:

oracle-clue validar ../revisiones/informe.json --paquete ../revisiones/contexto.json --repo .

Esperamos la respuesta exitosa:

Formato y vigencia verificados. No confirma los hallazgos ni autentica al revisor o al actor humano.

¿Qué comprobó Clue exactamente?

  1. Volvió a recolectar el contexto y comprobó que su estructura completa coincida con el paquete. Eso detecta discrepancias en las entradas seleccionadas; no autentica al autor ni demuestra que ningún archivo fuera de ese alcance haya cambiado.
  2. Validó informe.json contra hallazgos.schema.json.
  3. Comprobó que diff_sha256 y context_sha256 en el informe coincidan con el paquete.
  4. Comprobó que el hallazgo apunte a total.py, del lado head, entre las líneas 2 y 2, y que ese rango pertenezca a un hunk del diff. Un hunk también incluye líneas de contexto sin modificar; Clue no prueba que el defecto exista ni que haya sido introducido por el cambio.

Comprobación didáctica: ¿Cómo rechaza Clue una ubicación fuera del diff?

Para comprobar que la validación es real y estricta, abrí ../revisiones/informe.json en tu editor y cambiá la ubicación a una línea fuera de todos los rangos del paquete:

"start_line": 999,
"end_line": 999

Guardá y volvé a ejecutar oracle-clue validar:

oracle-clue validar ../revisiones/informe.json --paquete ../revisiones/contexto.json --repo .

Clue se detiene con error de inmediato:

CLUE: el rango del hallazgo no pertenece a ese lado del diff

Volvé a poner start_line: 2, end_line: 2 en informe.json antes de continuar.

PASO 08

Registrá las decisiones humanas por separado (Opcional).

Las decisiones humanas sobre qué hacer con cada hallazgo se guardan por separado según triage.schema.json. Esto permite que el informe técnico original se conserve sin sobrescribirlo.

Creá un script armar_triage.py para calcular el hash exacto del archivo informe.json y registrar una decisión que hayas tomado. Este paso es opcional: si todavía no hay una decisión, omitilo. El código sigue con el defecto; no lo declares corregido antes de corregirlo. Clue comprueba los campos y su enlace, sin verificar que la acción declarada se haya realizado:

"""Asistente externo para registrar decisiones explícitas, sin aprobar ni corregir código."""
import hashlib
from datetime import datetime, timezone
import json
from pathlib import Path

def main():
    informe_path = Path("../revisiones/informe.json")
    informe_bytes = informe_path.read_bytes()
    informe = json.loads(informe_bytes)
    print("Este asistente registra tu decisión; no verifica que sea correcta ni ejecuta correcciones.")
    finding_id = input("Id del hallazgo sobre el que decidiste: ").strip()
    if finding_id not in {item["id"] for item in informe["findings"]}:
        raise SystemExit("Ese id no pertenece al informe.")
    status = input("Decisión ya tomada (corregido, descartado o riesgo_aceptado): ").strip()
    if status not in {"corregido", "descartado", "riesgo_aceptado"}:
        raise SystemExit("No hay decisión válida; no se creó el registro.")
    reason = input("Motivo y evidencia de la decisión: ").strip()
    actor = input("Tu nombre: ").strip()
    if not reason or not actor:
        raise SystemExit("Falta motivo o responsable; no se creó el registro.")
    triage = {
        "schema_version": "oracle-clue.triage/v1",
        "report_sha256": hashlib.sha256(informe_bytes).hexdigest(),
        "decisions": [{"finding_id": finding_id, "status": status, "reason": reason,
                       "actor": actor, "at": datetime.now(timezone.utc).isoformat()}]
    }
    salida = Path("../revisiones/triage.json")
    with salida.open("x", encoding="utf-8") as file:
        file.write(json.dumps(triage, indent=2, ensure_ascii=False) + "\n")
    print(f"Decisión registrada en: {salida}")

if __name__ == "__main__":
    main()

Ejecutalo para crear triage.json:

uv run --no-project --python 3.13 python armar_triage.py

Ahora validá el conjunto completo pasando --triage:

oracle-clue validar ../revisiones/informe.json --paquete ../revisiones/contexto.json --repo . --triage ../revisiones/triage.json

Clue verifica que triage.json apunte al hash exacto del informe y que cada finding_id exista en el informe sin duplicados.

PASO 09

Qué pasa si el código cambia (Recuperación).

Ahora que detectaste el defecto en total.py, lo corregís en tu editor volviendo a return precio * cantidad y creás un nuevo commit en Git:

git add total.py
git commit -m "Corregir cálculo de total restableciendo multiplicación"

¿Qué ocurre si intentás validar el informe anterior ahora?

oracle-clue validar ../revisiones/informe.json --paquete ../revisiones/contexto.json --repo .

Clue lo rechaza inmediatamente:

CLUE: el paquete no coincide con el repositorio/contexto actual

El ciclo correcto de recuperación:

  1. El commit nuevo alteró HEAD. El paquete anterior contexto.json quedó obsoleto.
  2. Preparás un nuevo paquete con una ruta de salida nueva (ej. ../revisiones/contexto_v2.json).
  3. El revisor genera un nuevo informe para ese paquete.
  4. Validás el nuevo informe contra el nuevo paquete. El asistente de esta guía solo documenta el defecto sembrado: no lo reutilices para inventar ese hallazgo una vez corregido.

PASO 10

Diferencia entre Oracle Clue y el juicio de Oracle.

Es común preguntarse qué diferencia hay entre Clue y Oracle (o Oracle Factory):

  • Oracle Clue: Es un inspector de integridad estructural. Trabaja a nivel de Git, diffs, hashes SHA-256 y rangos de líneas. Responde: «¿Este informe corresponde verdaderamente al diff entre estos dos commits?»
  • Oracle (metalenguaje): Es un evaluador de juicios de hecho. Trabaja a nivel de observaciones concretas contra medidas elegidas para requisitos; OpenSpec es una fuente posible. Responde: «¿Los hechos observados en las pruebas cumplen con las medidas acordadas?»
  • Oracle Factory: El alpha registra acuerdos, tareas, revisión externa y juicio de hechos. No ejecuta agentes, tests ni sensores, y su cierre es local.

Ninguna de estas herramientas aprueba automáticamente tu entrega ni reemplaza tu responsabilidad como desarrollador.

PREGUNTAS FRECUENTES Y DIAGNÓSTICO

Si algo no funciona como esperabas.

CLUE: guardá el paquete fuera del repo revisado

El argumento --salida no puede apuntar a un archivo dentro de la carpeta que estás inspeccionando. Usá una ruta como ../contexto.json o /tmp/contexto.json.

FileExistsError al ejecutar preparar

Clue crea los archivos de paquete en modo exclusivo ('x') para proteger paquetes anteriores de ser sobreescritos accidentalmente. Elegí un nombre nuevo (ej. contexto_v2.json) para conservar el paquete anterior.

CLUE: hay cambios versionados sin commit

Tenés modificaciones sin guardar en Git. Ejecutá git status. Revisá esos cambios y guardalos en un commit si corresponden a la versión que querés revisar.

CLUE: el diff está vacío

Los commits elegidos no tienen diferencias de archivos; también puede pasar con commits distintos. Clue necesita revisar cambios reales entre dos commits distintos. Utilizá HEAD~1 o el hash de un commit previo.

CLUE: el rango del hallazgo no pertenece a ese lado del diff

Las líneas start_line y end_line del informe deben caer dentro de los rangos del lado actual (head) o anterior (base) registrados en contexto.json. Los rangos también incluyen líneas de contexto que no cambiaron. El revisor debe justificar que el problema pertenece al cambio; Clue no demuestra esa relación.
